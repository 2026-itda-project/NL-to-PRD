# 시나리오, 정답 v1.0

**상태: 사용자 승인 완료 / 정답 v1.0 고정. 실행 및 채점 결과는 실행별 보고서에 기록한다.**

이 정답은 현재 LLM 출력을 그대로 정답화한 것이 아니다. 사용자 입력에서 확인할 수 있는 사실과 제품 동작상 필요한 결정을 기준으로 만든 검토 초안이다. 필수 Gap, Blocking 및 분모는 사용자 승인 기준으로 고정했다. [채점 규칙과 계획](README.md)을 함께 읽는다.

표의 C, N/B, N/N은 채점 규칙에 정의한 상태, Requirement.blocking 조합이다. R/G/A/F 번호는 평가 기준 ID이며 생성 모델이 그대로 출력해야 하는 ID가 아니다. 모든 사례에서 `proposed` 생성, 미언급 내용을 Requirement로 채우기, 정책 대안을 임의 확정하기는 금지한다. 명시 사실을 proposed로 출력하면 사실 회수는 인정하고 상태 오류와 금지 출력에 각각 기록한다. 아래 관련 R 및 연결 표시는 참조 검사 기준이며 Gap 의미 회수의 필수 조건이 아니다. 추출 누락으로 연결할 ID가 없는 경우 의미 회수와 참조 대상 부재를 분리한다. 계약 실패로 응답이 없으면 중간 결과를 추정해 채점하지 않는다.

## L01 - 현재 사용자 입력

**모델에 전달할 입력**

> 관리자가 직원의 휴가를 승인하거나 반려할 수 있는 직원 휴가 서비스 만들어줘

**필수 사실**

| ID | 의미 단위 | 상태 |
| --- | --- | --- |
| R1 | 관리자 역할이 있다 | C |
| R2 | 필수 채점에서 제외: 직원은 휴가의 대상이며 시스템 사용자 역할은 명시되지 않음 | - |
| R3 | 관리자가 직원 휴가를 승인할 수 있다 | C |
| R4 | 관리자가 직원 휴가를 반려할 수 있다 | C |

R2 번호는 변경 추적을 위해 남기며 필수 사실 분모에 포함하지 않는다. 직원이 휴가의 대상이라는 설명은 허용한다. 이를 시스템 사용자 역할이나 신청/조회 권한으로 확장하면 근거 없는 추론으로 기록한다.

**필수 Gap**

- G1 - 휴가 건을 누가 어떤 경로로 생성/접수하는가. `core_flow`, blocking=true, 관련 의미 R3/R4. 하나의 생성/접수 결정으로 채점하며 직원 직접 신청을 전제로 하지 않는다.
- G2 - 관리자가 처리할 수 있는 직원의 범위. `permission_approval`, blocking=true. 승인 권한의 대상이 불명확하다. 관련 의미: R1/R3/R4.
- G3a - 승인/반려를 수행할 수 있는 선행 상태. `state_change`, blocking=true, 관련 의미 R3/R4.
- G3b - 처리 완료 후 재처리 가능 여부. `state_change`, blocking=true, 관련 의미 R3/R4.

**허용 Gap:** A1 수정/취소 정책, A2 반려 사유 정책, A3 휴가 유형, 신청 정보. 이 초안에서 필수 회수율에는 넣지 않는다. A1의 blocking=true는 상태 무결성에 필요한 이유가 있으면 허용한다. A2는 기본적으로 nonblocking, A3는 핵심 신청 데이터인지 단순 선택 UI인지 구분해 판정한다.

**금지:** F1 직원 직접 신청을 confirmed로 추가; F2 승인/반려 기능 유무를 미정으로 처리; F3 직속 관리자, 다단계 승인, 연차 차감, 통계를 필수 기능으로 확정; F4 로그인 방법, 화면 배치만으로 무조건 핵심 차단.

**고정 기준:** G1/G2/G3a/G3b를 필수로 채점한다. A1/A3는 현재 허용 항목이며 평가 결과를 본 뒤 필수로 바꾸지 않는다.

## L02 - 정책이 충분한 휴가 처리 범위

**입력**

> 사내 휴가 처리 데모다. 사용자 역할은 직원과 관리자이며 확인된 계정과 소속팀 정보가 제공된다. 직원은 본인 휴가를 시작일, 종료일, 사유로 신청한다. 시작일은 오늘 또는 미래 날짜이며 종료일은 시작일 이상이어야 하고, 본인의 대기, 승인 건과 날짜가 겹치면 거부한다. 관리자는 같은 팀 직원의 대기 건만 한 단계로 승인 또는 반려한다. 반려 사유는 필수이며 직원에게 내역으로 보인다. 생성 상태는 대기이고 승인, 반려는 최종 상태다. 직원은 대기 건만 취소할 수 있으며 취소도 최종 상태다. 수정은 지원하지 않고 다시 신청한다. 이미 처리된 건에 대한 처리는 거부한다. 직원은 본인 내역만, 관리자는 같은 팀 내역만 조회한다. 휴가 유형 구분, 연차 잔액, 차감, 휴일 계산, 알림, 외부 연동은 제외한다.

**필수 사실**

**고정 기준:** 명시된 범위에서 필수 Gap 0개로 고정한다. 추가 날짜 경계 등의 제안은 위 허용 기준을 적용하며 필수로 추가하지 않는다.

**짝 비교:** L02에서 없던 승인 범위 Gap과 N/B 항목이 L03에서 나타나고, 나머지 결정은 유지되는지 본다.

## L04 - L01과 같은 의미의 다른 표현

**입력**

> 직원 휴가 서비스가 필요해. 직원의 휴가 건에 대해 관리자가 반려할 수도 있고 승인할 수도 있게 해줘.

**필수 사실:** L01 R1, R3, R4와 동일(C). R2는 동일하게 필수 분모에서 제외한다.

**필수 Gap / 허용 Gap / 금지:** L01 G1/G2/G3a/G3b, A1~A3, F1~F4 및 직원 역할 경계와 동일. L04는 대표 매크로 집계에서 제외하고 L01과의 표현 안정성 비교로 보고한다.

**짝 비교:** 문장 순서와 표현 변화만으로 직원 신청 기능이 새로 confirmed 되거나 필수 Gap이 사라지는지 확인한다. Requirement 개수, ID, 문구 일치는 요구하지 않는다.

## L05 - 직원 직접 신청을 명시적으로 제외

**필수 사실**

| R1b | 직원 역할 | C |
| R1c | 계정과 직원 목록 제공 | C |

## L06 - 서로 충돌하는 취소 규칙

**입력**

> 직원은 본인 휴가를 시작일, 종료일로 신청하고 관리자는 전 직원의 대기 건을 한 단계로 승인 또는 반려한다. 계정과 역할은 제공된다. 날짜 순서가 잘못되거나 같은 직원의 대기, 승인 건과 겹치면 거부한다. 직원은 승인 전 대기 중인 자기 신청을 취소할 수 있다. 모든 휴가 신청은 등록 후 취소할 수 없다. 생성 상태는 대기, 승인, 반려, 취소는 최종 상태다. 처리된 건의 재처리는 거부한다. 직원은 본인 내역, 관리자는 전체 내역을 조회한다. 수정, 반려 사유, 연차 계산, 알림, 외부 연동은 제외한다.

## A01 - 장비 대여의 반납 처리 권한 누락

**필수 사실**

| ID | 의미 단위 | 상태 |
| --- | --- | --- |

| R2 | 직원의 대여 가능한 장비 선택, 신청 | C |

| R4 | 승인 시 대여 중, 반납 시 대여 가능 | C |

| R6 | 같은 장비의 동시 이중 대여 금지 | C |

**필수 Gap:**

- G1 반납 처리를 수행할 수 있는 주체. `permission_approval`, blocking=true, 관련 의미 R5.
- G2 대기 신청이 해당 장비를 점유하는가. `core_flow` 또는 `exception_handling`, blocking=true, 관련 의미 R2/R3/R6. 대기 중 다른 신청을 받을 수 있는지와 같은 결정이며, 이미 확정된 동시 이중 대여 금지를 다시 묻는 것은 아니다.

**허용 Gap:** A1 신청 취소, 승인 거절, A2 파손, 분실 처리. A2는 별도 관리 범위를 강제로 확장하지 않는 nonblocking만 허용. A3 복수 대기 신청을 허용하는 경우의 처리 우선순위는 조건부 허용 Gap이다. G2의 추가 필수 단위로 세지 않으며, blocking=true는 실제 처리에 필요한 근거가 있을 때만 허용한다.

**고정 기준:** G2의 대기 점유 여부는 필수로 유지한다. 대기 접수 정책과 동시 대여 금지를 구분하고 우선순위를 G2에 섞어 채점하지 않는다.

## D01 - 외부 연동은 필수지만 대상 미정

**입력**

> 사내 문서 공유 서비스다. 직원 계정과 소속팀은 제공된다. 작성자는 문서를 올리고 같은 팀 직원만 문서를 조회하거나 다운로드한다. 다른 팀 접근은 거부한다. 파일은 회사가 사용하는 외부 저장소에 반드시 저장해야 하지만 연동할 저장소 제품과 인증 방식은 아직 미정이다. 공개 링크와 외부 고객 공유는 제외한다.

**필수 사실**

| ID | 의미 단위 | 상태 |
| --- | --- | --- |
| R1 | 직원/작성자 역할과 제공된 계정, 소속팀 | C |
| R2 | 작성자의 문서 업로드 | C |
| R3 | 같은 팀 직원만 조회, 다운로드, 타 팀 거부 | C |
| R4 | 회사 외부 저장소에 파일 저장 필수 | C |
| R5a | 저장소 제품 미정 | N/B |
| R5b | 인증 방식 미정 | N/B |
| R6 | 공개 링크, 외부 고객 공유 제외 | C |

**필수 Gap:**

- G1a 연동할 저장소 제품. `external_integration`, blocking=true, 관련 의미 R5a.
- G1b 사용 가능한 인증 방식의 제품 수준 조건. `external_integration`, blocking=true, 관련 의미 R5b.
- G2 저장 실패 시 문서 등록의 성공/실패 처리. `exception_handling`, blocking=true, 관련 의미 R2/R4.

출력 Gap 하나에 제품과 인증 조건이 모두 있으면 G1a와 G1b를 각각 회수한 것으로 인정한다. 같은 결정을 여러 번 표현해도 정답 단위당 한 번만 인정한다.

**허용 Gap:** A1 업로드 크기/파일 형식 제한, A2 삭제, 버전관리 범위. A1은 실제 처리 제약의 근거를 확인하고 Blocking을 검토한다. A2는 nonblocking만 허용.

**금지:** F1 Google Drive, S3 등 특정 제품 확정; F2 외부 저장소 필수 조건을 선택사항으로 축소; F3 OAuth 상세 구현이나 SDK를 제품 요구사항으로 확정; F4 공개 공유 기능 추가.

**고정 기준:** 인증 방식의 제품 수준 제약 확인과 세부 구현 설계를 구분한다. 구체 Header, SDK 설계까지 요구하는 Gap은 필수 정답으로 보지 않는다.

## 해석 시 주의사항

- L01/L04는 동일 정답의 표현 비교이며 두 사례를 모두 대표 평균에 넣지 않는다.
- L01, R01, E01, A01의 수정/취소는 허용 Gap이다. 유용한 질문을 불필요 Gap으로 감점하지 않으며, 이번 세트의 수정/취소 누락 탐지 범위는 제한적이다.
- 긴 명세인 L02/L05/R02의 과잉 차단과 L03/L06/S01의 차단 결과를 따로 비교한다. 현재 사례만으로 입력 길이가 판단의 원인이라고 결론 내리지 않는다.
- 아래 분모 표는 지정된 분해와 묶음 기준으로 고정했다. 남아 있는 묶음은 모든 구성 조건을 충족해야 1점을 인정하며 부분 점수는 없다. 시작일, 종료일, 사유 같은 한 입력의 구성 필드는 추가 분해하지 않는다. 실행 결과를 본 뒤 단위를 다시 나누지 않는다. v1.0 실행 결과를 본 뒤 분모를 변경하지 않는다.

## 회수율 분모

각 수치는 성공한 슬롯 한 개의 채점 기준이다. R은 상태와 관계없이 사실 회수를 먼저 판단하며, G는 필수 Gap만 센다. 허용 Gap과 제외된 L01/L04 R2는 분모에 넣지 않는다.

| 사례 | 필수 사실 R | 필수 Gap G | 비고 |
| --- | ---: | ---: | --- |
| L01 | 3 | 4 | 직원 역할 제외 |
| L02 | 25 | 0 | - |
| L03 | 25 | 1 | L02 상속 항목 전체 기재 |
| L04 | 3 | 4 | 표현 비교용, 대표 매크로 제외 |
| L05 | 13 | 0 | - |
| L06 | 10 | 1 | - |
| R01 | 3 | 3 | - |
| R02 | 9 | 0 | - |
| E01 | 6 | 3 | - |
| S01 | 7 | 0 | - |
| A01 | 6 | 2 | - |
| D01 | 7 | 3 | - |

묶음 단위의 일부만 맞힌 경우 회수 점수는 0이며, 부분 충족 내용은 오류 분석 메모에 남긴다. 여러 출력이 합쳐 묶음의 모든 조건을 보존하면 1점으로 인정한다. 정답 단위 하나의 상태가 출력들 사이에서 충돌하면 해당 단위의 상태는 오답이다.

- v0.2: L01/L04 직원 역할 필수 기준 제외, L03 조회/승인 범위 분리, L06 충돌 탐지와 상태 채점 분리, L01/R01/E01/D01 Gap 결정 단위 분해, A01 대기 점유 여부 명확화, S01/E01 짝 비교 추가. 입력 본문은 유지했다.
