# v1.0 실행 관측 및 검토 안내

이 문서는 자동으로 확인 가능한 결과와 원본 응답의 검토용 관측을 구분한다. 사실 회수율, Gap 회수율, 상태 정확도는 아직 사람 검토 전이며 확정 점수를 제시하지 않는다.

## 실패와 사용량

- 시도별 오류: `{"other_contract_unknown": 3}`
- Usage 미확인 시도: 3
- 실패한 호출에서 반환되지 않은 Extraction 및 Gap Usage는 추정하지 않았다. 확인 가능한 합계는 전체 실제 소비량과 다를 수 있다.
- 실패 슬롯의 중간 출력은 없으므로 오류 원인을 추출 내용이나 Schema 필드로 추정하지 않았다. 파이프라인을 수정하거나 서버 로그를 읽어 분류하지 않았다.

## 채점 진행 방법

- [채점표](scoring.csv)의 각 정답 단위에 대응 출력 ID와 필드, 판정, 원문 근거를 기입한다.
- [전체 시도와 원본 응답](attempts.jsonl)의 slot_id로 결과를 찾는다. Gap 및 Requirement ID는 각 응답 안에서만 해석한다.
- 상태와 Blocking은 회수 여부와 분리하며, 부분 충족 묶음은 0점 및 메모로 남긴다.
- 추가 허용/불필요 Gap, 중복, 과잉 확정, AC 및 참조 오류는 [추가 판정표](output-review.csv)에 기록한다.
- 허용 여부의 판정이 바뀌면 같은 결정이 있는 모든 응답을 재검토한다. 정답 기준은 실행 결과에 맞춰 변경하지 않는다.
- 현재 표의 미입력 칸은 0점이나 정답이 아니라 미채점이다. 실패 행은 채점 불가로 고정한다.

## 개선 검토 순서

1. 충분한 입력 및 제공된 조건을 다시 Blocking으로 만드는 사례를 먼저 검토한다.
2. 확정 사실과 미정을 한 Requirement로 묶는 상태 오류를 확인한다.
3. 필수 Gap 누락과 관련 Requirement 연결의 의미상 정확성을 확인한다.
4. 이번 실행을 기준 결과로 보존한 뒤 변경을 하나씩 적용하고 같은 v1.0으로 재평가한다.

아직 Prompt나 제품 코드를 개선하지 않았으며 개선 효과도 주장하지 않는다. 현재 결과는 전체 파이프라인 평가이며 Gap 모델 단독 성능이 아니다.
